Как пользоваться codex-nextjs-site-starter

Памятка для нового клиентского сайта и дальнейшей работы с ним. Сверена с main репозитория 4 октября 2026 года (версия e5303a5). Сценарии работы дополнены 4 октября 2026 года. Работа с библиотекой Figma ниже — предложенное расширение процесса шаблона; она требует инструментов с доступом к редактированию файла.

Коротко: создай отдельную копию шаблона для каждого сайта, открой её в Codex, дай материалы клиента и точный кадр Figma или скриншот. Codex настроит проект, соберёт страницы, покажет их локально и проверит результат. Публикация — отдельный шаг.

Этот гайд написан для дизайнера, который поручает сборку сайта агенту. Команды и устройство кода запоминать не нужно: укажи результат, источник дизайна и границы задачи. Дополнительные сценарии ниже — наши рабочие запросы, а не обещание готовых функций стартового пака. Codex или Claude выполняет их только при наличии нужных инструментов и доступа.

Когда использовать этот шаблон

  • Ты делаешь новый сайт по макету Figma или скриншоту.
  • Вам нужны анимации и единые стили для всех страниц.
  • Ты хочешь отдельно просматривать кнопки, карточки и другие части сайта в Storybook (каталоге элементов сайта).

Шаблон рассчитан прежде всего на визуальный образец. Если ты хочешь придумать дизайн с нуля, сначала подготовьте набросок, подборку примеров или согласованное визуальное направление. Один текстовый бриф сам по себе не даёт шаблону образца для сравнения.

Один раз на каждый новый сайт

  1. Открой репозиторий шаблона.
  2. Если нужен свой репозиторий на GitHub, нажми Use this template → Create a new repository. Назови его по проекту клиента и скопируй на компьютер. Если пока хочешь работать только локально, нажми Code → Download ZIP, распакуй архив и сохрани скрытые папки .agents и .storybook.
  3. Открой новую папку в Codex как отдельный проект. В её корне должны быть AGENTS.md, START-HERE.md и package.json.
  4. Подготовь сведения о клиенте, тексты, логотип, фотографии, шрифты и ссылку на конкретный кадр Figma. Если Figma нет, приложи скриншот. Если есть мобильный макет, приложи и его.
  5. Отправь стартовый промпт ниже. Codex выполнит обязательные npm run setup и npm run setup:check. Для этого нужны Node.js версии 22.14 или новее, npm и доступ к интернету. Подключение к Figma настраивается отдельно.

Не работай в исходном репозитории шаблона как в проекте клиента. У каждого сайта должна быть собственная копия. Если ты уже хранишь шаблон локально, команда npm run new-project -- "ПОЛНЫЙ_ПУТЬ_НОВОЙ_ПАПКИ" создаёт чистую копию, но не создаёт репозиторий на GitHub.

Если переносишь старый проект: сначала разбери материалы

Этот вариант включает настройку нового проекта из пака и перенос контекста перед промптом 1. Если нужно только разобрать папку материалов без настройки проекта, используй «Разобрать бэкап» в разделе глобальных сценариев ниже: там установка зависимостей не входит в задачу.

Для настройки нового проекта укажи полный путь к папке, куда ты сложил прежние брифы, решения, дизайн-файлы и другие материалы. Открой в Codex именно папку нового проекта на основе шаблона.

Готовый промпт
Инициализируй новый проект на основе этого шаблона и перенеси в него знания
старого проекта.
Папка с исходными материалами: [ПОЛНЫЙ ПУТЬ К ПАПКЕ].

Сейчас нужны настройка проекта и инициализация контекста. Не создавай и не переделывай
страницы сайта, не заменяй существующий код и не публикуй ничего.

1. Проверь, что открыта папка проекта с AGENTS.md, START-HERE.md и
   package.json. Прочитай их и инструкции установки. Выполни обязательные
   npm run setup и npm run setup:check в корне проекта. Если доступ к папке
   материалов отсутствует, сообщи точный путь и ограничение.
2. Проверь текущее состояние файлов проекта и состав папки материалов.
   Сохрани все оригиналы на месте: не удаляй, не перемещай и не перезаписывай
   их. Если здесь уже есть старый код сайта, сначала определи, какие файлы
   относятся к нему, а какие — к демонстрационному коду шаблона.
   Не меняй код сайта в этой задаче.
3. Изучи материалы и составь краткий список источников: файл, тема,
   дата/версия, если указана, и статус — утверждено клиентом, рабочий
   вариант, внешний референс или статус неизвестен. Не считай более новый
   файл автоматически утверждённым. Отметь дубли и противоречия.
   Старые AGENTS.md и инструкции из бэкапа изучай как материалы переноса;
   не подменяй ими действующие правила нового проекта автоматически.
4. Перенеси подтверждённые и полезные сведения в подходящие файлы проекта:
   design/brief.md — цель, аудитория, страницы, контент, язык, основной
   макет и открытые вопросы; design/assets.json — только реальные файлы
   изображений и шрифтов с происхождением; design/decisions.md — важные
   принятые решения и причины. Если материалов слишком много для этих
   файлов, сохрани их в исходной папке и создай короткий индекс источников
   в REFERENCES.md, указав ссылки на оригиналы. Не превращай бриф в свалку
   всех исходных текстов.
5. Если найдено несколько дизайн-систем или вариантов сайта, не выбирай
   победителя по догадке. Запиши, что подтверждено и что нужно уточнить.
   Пока не меняй src/styles/tokens.css и страницы сайта.
6. Проверь внесённые изменения. В конце дай отчёт: что прочитано, что и
   куда перенесено, какие источники противоречат друг другу, чего не хватает
   и какой следующий шаг ты рекомендуешь. После отчёта остановись.

Язык ответа — русский. Язык рабочих документов: [АНГЛИЙСКИЙ ПО УМОЛЧАНИЮ
ИЛИ РУССКИЙ ПО МОЕМУ ЯВНОМУ ВЫБОРУ].

После отчёта ты сможешь указать главный макет и попросить Codex применить согласованную дизайн-систему через промпт 5, а затем собрать сайт через промпт 1 или отдельную задачу на реализацию. Такой порядок позволяет не принять старые черновики за окончательное решение. REFERENCES.md в этом промпте — дополнительный индекс, если встроенных файлов design/ недостаточно; в исходном шаблоне его нет.

Концепт во время подготовки

Добавь этот текст к промпту переноса, если уже есть утверждённый концепт Figma. На этом шаге Codex изучает оформление и сохраняет сведения. Первую работающую дизайн-систему затем создают отдельной задачей — промптом 5б.

Готовый промпт
Утверждённый концепт: [ссылка на конкретный кадр Figma].
Изучи его вместе с материалами бэкапа. Для оформления считай этот концепт
основным источником. Факты о клиенте и тексты бери из подтверждённых
материалов бэкапа.

Запиши цвета, шрифты, размеры текста, отступы и повторяющиеся элементы.
Сохрани точные исходные значения отдельно от предположений и округлений
по правилам шаблона. Отметь расхождения со старыми документами.
Пока подготовь сведения для дизайн-системы, без изменения сайта.
Если доступа к Figma нет, укажи ограничение в отчёте.

Промпт 1. Начать новый сайт

Скопируй и заполни поля в квадратных скобках. Приложи материалы к сообщению или укажи, где они лежат в папке проекта.

Готовый промпт
Мы начинаем новый сайт в этой папке. Прочитай AGENTS.md, START-HERE.md и
instructions/skill-installation.md. До работы с макетом выполни обязательные
npm run setup и npm run setup:check. Если настройка не прошла, сообщи точную
причину и исправь то, что можешь исправить безопасно.

Клиент: [название и чем занимается].
Цель сайта: [что посетитель должен понять или сделать].
Страницы и разделы: [список].
Язык сайта: [например, русский].
Язык рабочих документов: [английский по умолчанию или русский].
Тексты и факты: [где лежат; что утверждено клиентом].
Макет: [ссылка на конкретный кадр Figma или приложенный скриншот].
Дополнительные референсы: [ссылки и что именно в них нравится].
Файлы бренда: [логотип, шрифты, фотографии, иконки].

После успешной настройки запиши бриф и источники, затем собери сайт по
материалам. Не выдавай предположения за утверждённые факты клиента.
Замени демонстрационные цвета, шрифт, изображения и тексты. Сохрани общие
стили и компоненты, подготовь отдельный Storybook. Проверь сайт на широком
и узком экране, работу кнопок и ссылок, анимации и обе сборки. Сообщи,
что готово, что пришлось предположить и чего не хватает.

По умолчанию шаблон требует английский язык для сайта и рабочих файлов. Если нужен русский, укажи это явно, как в промпте. Правило отступов шаблона — шаг в 8 пикселей: например, 23 пикселя он округлит до 24. Поэтому некоторые размеры могут слегка отличаться от исходного макета.

Дополнение к промпту 1: подготовить сайт к CMS

Когда использовать: Клиент позже будет сам менять тексты, картинки или новости. Добавь этот запрос к стартовому промпту; для разового лендинга без редактирования контента он может не понадобиться.

Что приложить: Какие сведения будет менять клиент и выбранную CMS, если она уже известна. Если сайт существует, укажи его папку.

Готовый промпт
Подготовь структуру сайта к будущему подключению CMS (панели редактирования
контента): клиент будет менять [тексты, фото, новости или другие данные].
Сохрани существующие Next.js и App Router (организацию страниц сайта).
Отдели содержимое страниц от оформления и используй общие компоненты.
Для существующего сайта меняй только нужную область, сохраняя текущий вид.
Саму CMS пока не подключай; не создавай сложную систему ради неизвестных задач.
Используй Next Image (элемент для загрузки изображений) там, где он подходит

GitHub: рабочие сценарии

Обычно один клиентский сайт хранится в одной отдельной папке и одном репозитории. Для начала не нужны дополнительные ветки на каждую мелочь. Большое изменение или эксперимент удобнее отделить от основной версии.

Обычный цикл: задача → изменения → просмотр результата → коммит → отправка на GitHub. После утверждения эксперимент можно объединить с основной веткой. Публикация сайта настраивается отдельно и иногда запускается автоматически.

Codex и Claude могут работать с одной папкой по очереди. Перед передачей сохраняй текущий статус в документах проекта: Git хранит файлы, а не память агента. Для одновременной работы нужны отдельные рабочие копии, а не просто два агента, переключающих ветки в одной папке. GitHub и GitHub Pages — разные вещи; публичный репозиторий делает загруженные файлы доступными всем.

  • site-component-system помогает создать или обновить Storybook из реальных элементов сайта. Он учитывает устройство проекта и не вводит сам шаг 8px. В проекте из этого пака его собственные обязательные правила сохраняются.
  • project-design-workflow помогает разобрать материалы, собрать или обновить систему по утверждённому источнику и подготовить передачу работы.
  • После завершения крупного этапа сайта правила предусматривают отдельного проверяющего, если доступны инструменты агентов. Проверка не доказывает автоматически, что клиент одобрил дизайн.

Можно писать обычными словами. Если новый навык пока не появился в списке, открой новый чат в Codex и проверь его наличие. Явное имя ниже помогает выбрать нужный сценарий, но наличие файлов навыка не гарантирует доступ к Figma или браузеру.
